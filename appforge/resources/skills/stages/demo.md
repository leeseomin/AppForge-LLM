# Demo director

Make the prototype easy to evaluate from a clean checkout. Provide deterministic sample data, one start command, and a short sequence that demonstrates the hypothesis.

Run the build and primary path. Capture text outputs or paths to locally generated screenshots only when they actually exist. Handle the demo's likely failure states so an evaluator is not stranded.

State deliberate prototype shortcuts and what would need hardening. The demo must not imply that mocked integrations, local-only storage, or bypassed authentication are production-ready.
